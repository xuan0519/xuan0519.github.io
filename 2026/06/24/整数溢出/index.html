整数溢出

整数溢出

1. 核心概念

整数溢出是指当一个整数变量的值超出了它所能表示的最大值或最小值范围时，其内部二进制位发生进位或借位，导致数值变成了一个完全意想不到的值（通常是在模运算范围内的回绕）。

  • 宽度溢出（Width Overflow）： 比如 8 位无符号整数（uint8_t），最大值为 255。255 + 1 会变成 0。
  • 符号溢出（Sign Overflow）： 有符号整数的最高位是符号位。当正数过大溢出时，可能会变成负数。例如 32 位有符号整数最大值 2147483647 + 1 会变成 -2147483648。

2. 常见漏洞场景与成因

整数溢出本身往往不会直接导致任意代码执行，但它通常会引发逻辑错误，进而导致堆栈溢出或任意地址读写。

A. 绕过大小检查（Size Check Bypass）

这是最常见的 Pwn 题套路。程序限制了输入大小，但可以通过溢出绕过检查。

B. 负数变正数（有符号与无符号混用）

在 C 语言中，有符号数与无符号数比较或转换时容易出漏洞。

C. 乘法溢出引发堆溢出

在动态内存分配（malloc）时，计算总大小发生乘法溢出。

3. Pwn 漏洞利用思路

  1. 审计源码/逆向分析： 寻找 malloc(count * size)、read(fd, buf, len)、memcpy 等函数，并向上追溯 count 或 len 的类型（关注 short、int、unsigned 的隐式转换）。
  2. 寻找触发点： 计算临界值。
    • 想让有符号数变成负数：输入 0x7fffffff + 1 = 0x80000000 (-2147483648)。
    • 想让大数变成小数（绕过截断）：输入 0x10000 + target_size (对于 16 位整数)。
  3. 结合其他漏洞： 整数溢出通过破坏长度检查后，下一步通常是构造滑行 Payload 覆盖返回地址（栈溢出）或修改 Heap Chunk 的 Metadata（堆溢出），最终劫持执行流（如通过 ret2libc 或 one_gadget）。

4. 防范与修复

  • 使用标准库中安全的类型和函数，避免隐式类型转换。
  • 利用 GCC 编译器的内置函数进行溢出检查，例如 __builtin_add_overflow。
  • 在进行乘法或加法前，先进行边界逻辑验证（如 if (count > MAX / sizeof(int))）。
